# Badge

A badge is a short label that shows the status or category of something, such as whether a stream is running or a configuration is enabled.

<Canvas of={BadgeStories.Light} />

<Controls of={BadgeStories.Light} />

## Usage

### Color

Badges use five semantic colors: `primary`, `success`, `warning`, `danger` and `gray`. Pick the color for its meaning, not for decoration, and always pair it with a clear text label.

<Canvas of={BadgeStories.AllColors} />

### Variant

- **Light** (tinted background) is the default. Use it in most contexts, such as table cells and status columns.
- **Filled** (solid background) is for emphasis, for example a "default" marker that should stand out from a plain informational badge.

<Canvas of={BadgeStories.Filled} />

### Dot

Add a dot for a **live, actively changing** process state, such as a stream's Running/Paused state or a system job that is running, queued or complete.

Leave it off for a **static, stored** attribute, such as Enabled/Disabled settings, install or edit state, or severity. Nothing is happening right now, so the dot reads as noise instead of a live signal.

<Canvas of={BadgeStories.WithDot} />

### Icons

Use `leftIcon` or `rightIcon` with any icon from the Graylog icon set. A dot replaces the left icon.

<Canvas of={BadgeStories.WithIcon} />

## Accessibility

- Pass `onClick` to make the whole badge a real, keyboard-accessible `<button>`. Without it, the badge is a non-interactive `<span>`.
- Don't rely on color alone: the label text must say what the status is.
