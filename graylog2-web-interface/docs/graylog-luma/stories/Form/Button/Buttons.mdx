# Buttons

Buttons let users take actions and make choices with a single click or tap. Use them to submit forms, open modals, confirm decisions, or start a process. A button's label should say exactly what will happen when it's pressed.

If an action takes the user somewhere else, such as another page or the documentation, use a link instead.

## Hierarchy

Choose emphasis based on how important the action is compared with everything else on the surface. Most screens need one primary button and a few secondary or tertiary ones.

## Button or Link?

Buttons do things. Links go places. Screen reader users hear "button" or "link" and expect different behavior, so the element must match what happens.

## Sizes

Buttons come in three sizes. Small (sm) is the default for most interfaces. Extra small (xs) is for compact contexts where space is limited, such as tables, cards, and infographics. Medium (md) is for larger layouts or standalone actions that need extra emphasis.

## Writing Button Labels

Labels should tell users exactly what will happen. Start with a verb, keep it to one to three words, and use sentence case: capitalize only the first word and proper nouns or acronyms, such as "Export CSV".

## Placement and Usage

Consistent placement helps users find actions quickly, build familiarity, and avoid mistakes. Which side matters less than doing it the same way everywhere: place actions where the task ends, and keep the order within each context identical across the product.
